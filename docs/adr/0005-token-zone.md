# Token 分区：请求列表优先，mock 先行

截图来源的使用统计页（总数 + 趋势 + 请求日志）要移植为刘海新分区，对标网速插件式常驻子功能。

决定：新分区 `token` 与概览/设置并列，进 `zoneOrder` 与 `zonePanelHeight` 查表；首版做请求列表（时间 + 模型 + 输入/输出 + 用时 + 成本 + 状态码）+ KPI 单行（Tokens / 缓存率 / 调用 / 成本，2026-09-08 用户紧凑版定稿）；趋势图不做；数据源后接，首版用截图同构 mock 定版式。

## Considered Options

- 放概览区并排配额卡：被否——概览内容槽仅 106pt，5 列列表放不下，还会挤 Tray。
- 放设置区下面：被否——用户明确点开才看，设置区 195 槽已接近打满（余量 11.2pt），再塞列表必溢出。
- 首版全量移植（顶部 + 趋势 + 表格）：被否——趋势图 + 9 列表格在 600pt 宽面板放不下，高度表要爆；先列表验证分区骨架，统计与趋势后续工单加。

## Consequences

- `ContentType` 加 case，`zoneOrder` 变三区循环，顶栏点击/横扫/方向键语义自动跟随。
- 高度表 `.token: 254`（03 工单探针实测：内容自然高 164 = KPI 单行 + 表头 + 5 行；164+29+60 = 253，取 254 留 1pt 余量，与设置区同口径）；`hostedViewHeight` 仍取 max（设置 284 不变）。
- 状态码着色沿用配额环语义（200 绿、429 红），与 `QuotaCardView.ringColor` 同一阈值语言。
- 数据源工单另起：本地日志扫描 vs API 轮询待定，mock 模型要预留替换缝。
