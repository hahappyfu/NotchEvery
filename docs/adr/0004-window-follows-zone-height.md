# 窗口高度跟随分区：修设置区显示不完与高度守卫崩溃

用户报告设置区（第二页）显示不完。排查发现两个同源问题：

1. 窗口被钉死 200pt 高，设置面板 284pt 伸出窗口的下半截系统根本不画（AppKit 裁剪）。旧注释把"向下溢出窗口"当成可行策略，实际不可行。
2. 高度守卫断言崩溃（三次 .ips 同一位置，含改动前）：设置区内容自然高超过内容槽 195。64px 玻璃卡菜单时代 natural≈214；去卡片化后实测 194.0，恰好回归表内。

决定：窗口高度跟随当前分区（展开按高度表，收起回 200），0.3s 动画过渡；pinnedContentSize 同步当区值，hosting 隐式 resize 也落在正确尺寸。高度表不动（实测概览 106/106、设置 194/195）。

## Considered Options

- 只加高高度表：被否——窗口 200 不动的话，表再高也画不出来。
- 去掉守卫断言：被否——断言本次立功，暴露了真实溢出；删断言等于拆烟雾报警器。
- 窗口瞬间跳变：被否——分区切换弹簧动画期间面板 bottom 会被硬裁 one frame，0.3s 过渡盖住。

## Consequences

- 新增分区必须进高度表，否则窗口高度回落到 hostedViewHeight（max 值兜底）。
- NotchWindowController 新增 Combine 订阅，destroy 里清理；屏幕参数变化重建窗口时订阅重建。
- 单元测试 target 的 `import NotchEvery` 模块名问题仍在（预置，与本次无关），高度数值契约靠守卫实测 + 表值测试双锁。
