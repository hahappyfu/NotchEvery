# 内容自适应面板：分区内容决定面板尺寸

`zonePanelHeight` 查表（520 定宽 + 165/224/… 定高）导致内容被裁（圆环半切）或下方留白——窗口先定死、内容再往里塞。以 ADR-0008 起反过来：内容量出尺寸，面板跟着走。

## Decision

- **驱动**：面板宽高均跟随当前分区内容（Zone Content）自然尺寸；520 宽度锁定解除（dots 已移到底部中间，原防左右跳理由消失）。
- **有界**：最小 320×120，最大 640 宽 × 屏幕高 40%；超限由内容区内部滚动/裁剪吸收，外层尺寸不受内部超大影响。
- **锚定**：顶边中心钉死，只往下和向两侧长；顶边位置 = 物理刘海下沿 + 8pt，刘海区只画背景、不放内容（动态避让，按 `deviceNotchRect` 逐屏取值）。
- **动画**：宽高同一条弹簧曲线过渡，贴苹果风格。
- **范围外**：设置 Popover 保持不动；dots 按参考图重做为霜化玻璃悬浮胶囊（见下）。
- **dots**：去黑底，霜化玻璃胶囊悬浮、两点居中（激活白、非激活 `white 0.35`），与内容拉开间距、严格居中，具体间距实现时对照参考图定。

## Considered Options

- A（只高度自适应、宽度继续锁 520）：被否——用户明确宽高都跟，锁宽理由（左上菜单栏）已不存在。
- B（无界自适应）：被否——Tray 50 文件 / Token 50 行会盖住半屏；必须有界 + 内部滚动。
- C（固定值避让刘海，如一律 32pt）：被否——14/16 寸刘海高度不同、无刘海外接屏又多出空白；用逐屏检测值 + 8pt。
- D（dots 去黑底无底悬浮）：被否——用户指定参考图，玻璃胶囊质感。

## Consequences

- `zonePanelHeight`、`zonePanelWidth`、`hostedViewHeight = max()`、`zoneContentHeight = H − spacing×2` 整套查表语义删除；`ZoneHeightGuard` 从"断言守卫"转为"测量驱动"（量宽 + 高，钳制后驱动面板/窗口）。
- `TabMetricsTests` 中锁定 165/224/195/300 的断言随实现删除或改写；`headerSlotHeight = 29` 保留（他人测试锁定，不作语义用途）。
- 窗口定位逻辑改为顶边中心锚定；分区切换时面板宽度会跳（接受，不再钉死）。
- 数据源仍 mock，全程未碰。
