# 面板结构定案 D：概览融合 + 诊断一级页

解锁能力并入后，面板长这样：**概览页把额度与守护并列成两张卡**（沿用 C 变体的融合版式），**诊断时间线提为一级分区**（横扫一格可达）。顶层由两页变三页——概览 / Token / 诊断；设置仍不占分页（ADR-0007），4 个低频开关（输入活动保护、手动锁屏保护、iMessage 通知、靠近唤醒）收进「设置 ▸ 解锁」。选 D 而非纯 C 的理由是**可达性**：诊断是「为什么没解锁」的答案，而那一刻正是你最急着要看它的时候，把它埋进「右键 → 设置 → 分段」是功能性缺陷；选 D 而非 A（解锁与诊断各占一页）的理由是**版面**：A 的解锁页只有 3 个开关，过于空旷。

## Considered Options

- **A 扁平 4 页**（概览 / Token / 解锁 / 诊断）：诊断同样一格可达，但多出一个空旷的解锁页，顶层导航变长，否决。
- **B 守护条 + 二级推入**：状态常驻可见是它的本事（补上了没有菜单栏图标后的可见性缺口），代价是多一层导航与返回成本；而「诊断」的使用时机恰恰不容许多一层，否决。
- **C 概览融合 + 设置内嵌套**：融合版式最受认可，但诊断埋得最深，否决。其版式被 D 继承。

## Consequences

- **对 ADR-0008 的实测输入：诊断页决定面板宽度下限。** 面板宽度是内容驱动的（加宽是合法解，不是妥协）。以岛体宽 420px 为基准实测三个视图——诊断 420×299（比值 **1.40**）、设置 ▸ 解锁 420×294（**1.43**）、概览 420×245（**1.71**）——**均低于 1.75 下限**，即合并后**面板整体会比现在宽**（诊断页约需 524px 才达标）。备选方案是让诊断页只显示最近 3 条 + 「全部」入口，留待实现时用真实数据判断 3 条够不够。
- 视觉基准与逐视图实测：`docs/superpowers/prototypes/2026-09-13-unlock-zone-variants.html`（`?variant=D&sub=0|2|3` 可直接分享；原型内 `几何实测` 卡实时显示尺寸、比值与达标所需宽度）。
- 原型阶段修掉的两处版式缺陷记录在此，避免实现时重犯：守护卡在 356px 内容宽下会把设备名与阈值折行；失败提示条同样会折行、自己给自己加高度——两者都需单行省略而非换行。
- CONTEXT.md 的「分区」词条将在实现落地时更新（本仓库惯例：CONTEXT.md 描述代码现状，决策由 ADR 承载，参见 ADR-0010）。
