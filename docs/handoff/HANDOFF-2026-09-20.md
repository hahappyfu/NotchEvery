## 一句话现状

Qoder 网关新增**内嵌式多凭据账号池**（撞日限自动换号、客户端无感），并把上游从被自动探测带偏的
`lingma.alibabacloud.com` 纠正到 `gateway.qoder.com.cn` —— **`/v1/models` 因此从 4 个变 14 个**。
新实例常驻 **`127.0.0.1:8096`，且当前这个 Claude 会话就正跑在它上面**。
8095 保留为回退，自 16:20 起已无流量。池内 4 个号**全是 Pro Trial、13 天后集体到期**
—— 这是比"号不够"更硬的约束（详见「账号容量」节）。
PID 会随换版改变，别信文档里的数字，用 `lsof -i :8095 -i :8096 | grep LISTEN` 现查。

## 今天证实的事实（带出处，直接采信）

- **上游域名是最大的一根杠杆**。`internal/remote/client.go` 的 `DefaultBaseURL` 写的是
  `lingma.alibabacloud.com`，而本仓库 `README.md` 开头宣称的是 `gateway.qoder.com.cn` —— **上游自相矛盾**。
  自动探测优先读缓存 `~/.config/qodercn-gateway/remote-base-url.json`，一旦落进 lingma 就一直用 lingma。
  两域名实测对照（同一账号、同一秒）：lingma 下 Kimi-K3 / DeepSeek-V4-Pro 全回
  `Agent quota exceeded`，切到 gateway 后**同一账号全部秒回**。
  ⚠️ `HANDOFF-2026-09-19.md` 第 30 行其实**早就写对了**（"模型流量 = gateway.qoder.com.cn"），
  但没有在配置里钉死，于是白踩了一整天。
- **`Agent quota exceeded` 不是额度，是打错域名**（见上）。此前把它当限流信号是误读。
- **两种 403 必须分开**（实测错误体）：
  - `{"code":"110","message":"Billing daily count exceeded"}` → **真·账号日限**，冷却到本地零点，**换号有效**
  - `{"code":"10605",...,"isQueued":true,"queueCount":7633,"queueType":"p3","retryAfterSeconds":30,"waitTime":232}`
    → **全局模型队列**，账号健康，**换号无效**（实测 5 个号 queueCount 均 7600±20）
- **Qwen3.8-Flash（`qfmodel`）确实是唯一 `price_factor: 0` 的真免费模型**，但排 p3 最低优先级队列。
  实测第一次重试 **6.5 秒**就进了 —— `waitTime: 232` 是最悲观估计，别当承诺。
- **免费 ≠ 零记账，但也确实不吃 300 池**：网关 usage 日志里 qfmodel 每轮 `credits=0.71~0.75`
  （29 万 token 上下文），而 4 个 Pro Trial 号的 `/quota` 全程 `used=0.0 / total=300`。
  即 credits 是服务端影子账，不进可见额度池。**再次印证** [[qoder-free-tier-shadow-billing]]。
- **权威模型目录有两个来源，无需抓包**：
  - `~/.qoder-cn/.auth/dynamic-texts.json` → `modelSelector.item.*` 命名空间，29 条中英文 display name + 描述
  - `https://gateway.qoder.com.cn/api/v2/model/list` → 带 `is_free` / `price_factor` / `max_input_tokens`
- **池的行为**：`Chat()` 有界重试（默认最多换 3 个号），每轮重建 request（body reader 会耗尽）
  且**整套 headers 重算**——`cosy_key` / `machine_id` / `clientIP` 三者必须由同一凭据派生，只换一部分会得到签名与身份不一致的请求。
  SSE 已开始吐字后不重试（半截响应无法回退）。
- **热加载已验证**：往池目录加号，不重启，`/v1/pool/status` 从 3 → 4 → 5 即时反映。
- **每次调用可归属到账号**（`e2b7e7d`）：`remote usage` 日志行带 `acct=<脱敏 user_id>`，
  与 `/v1/pool/status` 用同一个 `MaskAccount`，两边 token 可直接 grep 对接。
  注意**不能用 `CredentialSrc` 归属** —— `01a0be10` 与 `01a0be11` 都从当时的活跃
  `user` 导出，`Source` 字符串完全相同，按它聚合会把两个号并成一个。
  回溯某号当天烧了多少：
  ```bash
  grep "remote usage" logs/gateway_8096.log | awk '{for(i=1;i<=NF;i++){if($i~/^acct=/)a=$i;if($i~/^credits=/){split($i,c,"=");s[a]+=c[2]}}}END{for(k in s)printf "%s %.4f\n",k,s[k]}'
  ```
- **端到端换号已验证一次**：账号 `...4a9` 撞真日限 → 日志 `switching account (1/3)` → 冷却到零点 →
  下一个号补上 → **客户端拿到成功响应**，全程无感。

## 已放弃的策略（别重新论证）

「一行未改跟上游」在本仓库**主动作废**。账号池必须在 `Chat()` 里换号重试，外挂 watcher 做不到
"客户端那一发请求也成功"。用户明确选了内嵌式。
控制代价的方式是：**改动集中在 4 个已有文件**（`credentials.go` / `client.go` / `service.go` /
`server.go` + `main.go`），池逻辑全在新增的 `credential_pool.go` 里，`Chat()` 是唯一窄缝。
拉上游时冲突面预期只有 `Chat()` 函数体一处。

## 账号容量：现在是 4 个，但瓶颈不是数量

2026-09-20 实测汇总（`/api/v2/quota/usage` + `/api/v2/user/plan`）：

| 账号 | 套餐 | 300 池 | 加增池 | **试用到期** |
|---|---|---|---|---|
| `01a0b87c` | Pro Trial | 0/300 | **0/200** | **2026-10-03** |
| `01a0bc59` | Pro Trial | 0/300 | 无 | 2026-10-04 |
| `01a0be10` | Pro Trial | 0/300 | 无 | 2026-10-04 |
| `01a0be11` | Pro Trial | 0/300 | 无 | 2026-10-04 |

- **4 个全是 Pro Trial，13 天后集体到期**。到期后的形态已有活标本：被删掉的
  `01a0bd70` 是 `personal_standard`、`300 池 0.0/0.0`、`isQuotaExceeded=true`。
  **到期后这 4 个号会全部退化成那样，加号救不了。**
- **日限次数依旧完全不透明**：已撞限冷却的 `01a0b87c`，`/quota` 仍回报
  `isQuotaExceeded: false`、`used: 0/300`。所以给不出"每号每天 N 次"的可靠数字，
  只能撞到才知道（这本来就是池的职责）。旧记录里"821 次 / 129 次"那两个数**不可信** ——
  它们混进了 lingma 错误域名产生的假 `Agent quota exceeded`。
- **credits 随上下文线性增长**，实测本会话：`in=68 → 0.0060`、`in=294K → 0.7485`、
  `in=391K → 0.8998`。长上下文重负时段每号每天能撑的轮次会被这个曲线压下来。
- **多加号救不了免费模型的排队**：p3 队列全服共享（实测 5 个号 `queueCount` 都是 7600±20）。
  加号只解决"本账号当天次数用尽"，怕等就改走付费档 `Qwen3.7-Max`(0.5) /
  `GLM-5.3-Flash`(0.1、1M 上下文)。
- **`addOnQuota` 是今天才发现的字段**（`01a0b87c` 有 200 credits 加增池，其余三个没有）。
  含义、是否会先到期、能否主动消耗，都还没查。

## 失效时的排查顺序

1. `/v1/models` 只有 4 个 / 大面积 `Agent quota exceeded` → **先查 `remote_base_url` 有没有被自动探测带偏**
   （看 `~/.config/qodercn-gateway/remote-base-url.json`），显式钉死 `gateway.qoder.com.cn`

   `rate_limited` 15 分钟；也可清空 `remote_auth_pool_dir` 整体回退到单号
3. qfmodel 一直排队 → 是全局队列不是你的问题，换 `Qwen3.7-Max`(0.5) / `GLM-5.3-Flash`(0.1, 1M 上下文)
4. 都不通但 IDE 正常 → 上游换协议了，`qoderclicn --list-models` 交叉验证登录态与 key 是否改名

## 合规与风险（用户已知情，勿重复说教）

用账号凭据走非官方客户端大概率违反 Qoder 服务条款，存在限流/封号风险；`LICENSE = NOASSERTION`
不得二次分发。本次新增风险面：**5 个号在同机同出口 IP 高频轮换**可能加速触发 IP 维度风控
（今天撞的是账号日限，不是 IP，但队列拥堵与影子记账说明服务端有可见性）。
当前缓解：仅 loopback、入站 key、池目录 0700、并发沿用上游默认。
