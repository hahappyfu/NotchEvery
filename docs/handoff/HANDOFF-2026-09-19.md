## 已验证的事实（带出处，直接采信）
- 上游只有两个主机：`gateway.qoder.com.cn`（模型流量）、`openapi.qoder.com.cn`（控制面）。关键路径 `/algo/api/v2/service/pro/sse/agent_chat_generation`、`/api/v2/model/list`、`/api/v2/quota/usage`。
- 凭据：`~/.qoder-cn/.auth/user`（字段 `cosy_key` / `encrypt_user_info` / `access_token`），由 **`qoderclicn login` 产出**，IDE 登录态不会生成它。网关 `LoadCredential()` 在 `internal/remote/client.go` 的 `postSigned:677`、`listModels:788`、`Chat:876` **每请求重读、无缓存** → 换凭据文件即生效，不用重启。
- 模型名映射：`Qwen3.8-Flash → qfmodel`、`DeepSeek-V4-Pro → dmodel`。**未知名被原样透传**（`internal/service/service.go:746` 的 `default: return model`）→ 客户端必须显式填模型名，否则去向不可控。
- 实测通过：`/v1/chat/completions` 返回原生 `tool_calls`+`finish_reason=tool_calls`；`/v1/messages` 返回原生 `tool_use`+`stop_reason=tool_use`；两端 SSE 流式事件序列完整；`lsof` 确认仅 `127.0.0.1:8095`；`QODERCN_DISABLE_THINKING=1` 生效（`reasoning_content` 归零）。
- 额度：`user_type=personal_professional_trial`，`300 credits`。**【2026-09-19 深夜回填】**推断已证实但有修正：`/quota` 的 used 仍为 0（不计入 300 池），但网关 usage 日志显示每次调用有独立计量 `credits=0.21~0.29`（缓存命中）/ `2.4~2.6`（cached=0 冷启动）——即 price_factor=0 只免 300 池，服务端仍记 pre-discount charge（见 service.go:98 注释）。另：当前 Claude Desktop 会话实测 `ANTHROPIC_BASE_URL=127.0.0.1:15721/claude-desktop`（CC Switch 代理），并未走 8095；8095 的真实流量因 `QODERCN_DISABLE_THINKING=1` 全部 `reasoning_effort=none`（日志 `reasoning=0` 恒成立），Flash 目录的 low/medium/xhigh 三档未启用。

## 已踩过的坑（别再踩）
- `cockpit-tools`（17.9K★，支持 Qoder）**跟反代无关**：它的 Qoder 切号只写 IDE 的 `state.vscdb` 里 `secret://aicoding.auth.userInfo`，完全不碰 `.auth/user`。账号池这条路对反代无效。
- "网关默认监听 0.0.0.0"是**误读**——那段代码只在 `--export-server-bundle` 分支（`cmd/qodercn-gateway/main.go:232`），运行时默认一直是 `127.0.0.1`（`main.go:108`）。
- 独立 CLI 之前没装；现已装 `qoderclicn` v1.1.57（`~/.local/bin/`，用 `--skip-path` 装的，未改 `.zshrc`）。`qodercli`（国际版）不存在。
- 本机 `~/.qoder-cn/.models/*/catalog-v6` 是加密容器，静态取证到此为止。
